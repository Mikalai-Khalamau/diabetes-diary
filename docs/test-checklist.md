# Чек-лист функциональных требований — Дневник диабетика

Чек-лист охватывает все функциональные требования (FR1–FR20), сгруппирован по модулям приложения и содержит как позитивные, так и негативные проверки.

---

## Модуль 1: Аутентификация и пользователи (`auth`)

| ID проверки | Требование | Тип | Описание проверки | Ожидаемый результат |
|---|---|---|---|---|
| CHK-AUTH-01 | FR1 | Позитивный | Регистрация нового пользователя с валидными email и паролем | HTTP 201/200, пользователь создан в БД |
| CHK-AUTH-02 | FR1 | Негативный | Регистрация с уже существующим email | HTTP 409 Conflict |
| CHK-AUTH-03 | FR1 | Негативный | Регистрация с некорректным форматом email (без `@` или домена) | HTTP 422 Unprocessable Entity |
| CHK-AUTH-04 | FR2 | Позитивный | Проверка сохранения пароля в БД | Пароль хранится в виде bcrypt-хэша, открытый текст отсутствует |
| CHK-AUTH-05 | FR3 | Позитивный | Вход в систему с правильными учетными данными | HTTP 200, возвращается JWT-токен (`access_token`) |
| CHK-AUTH-06 | FR3 | Негативный | Вход с неверным паролем или несуществующим email | HTTP 401 Unauthorized |
| CHK-AUTH-07 | FR4 | Негативный | Запрос защищенного эндпоинта без заголовка Authorization | HTTP 401 Unauthorized |
| CHK-AUTH-08 | FR4 | Негативный | Запрос с просроченным или поддельным JWT-токеном | HTTP 401 Unauthorized |
| CHK-AUTH-09 | FR5 | Позитивный | Запрос `/api/auth/me` с валидным Bearer-токеном | HTTP 200, возвращает данные текущего пользователя |
| CHK-AUTH-10 | FR6 | Негативный | Попытка доступа/модификации чужой записи по ID другого пользователя | HTTP 404 Not Found (изоляция данных) |

## Модуль 2: Справочник продуктов (`foods`)

| ID проверки | Требование | Тип | Описание проверки | Ожидаемый результат |
|---|---|---|---|---|
| CHK-FOOD-01 | FR7 | Позитивный | Проверка авто-наполнения справочника при регистрации нового пользователя | В справочнике пользователя создано >100 базовых продуктов с углеводами |
| CHK-FOOD-02 | FR8 | Позитивный | Получение списка продуктов с пагинацией (`skip`, `limit`) | HTTP 200, возвращается срез продуктов согласно параметрам |
| CHK-FOOD-03 | FR8 | Позитивный | Создание нового пользовательского продукта (`POST /api/foods/`) | HTTP 201/200, продукт успешно добавлен |
| CHK-FOOD-04 | FR9 | Негативный | Создание продукта с именем, которое уже существует у этого же пользователя | HTTP 409 Conflict (уникальность имени) |
| CHK-FOOD-05 | FR10 | Позитивный | Редактирование названия и углеводов продукта (в т.ч. из базового набора) | HTTP 200, данные продукта обновлены |
| CHK-FOOD-06 | FR9 | Негативный | Обновление продукта на имя, конфликтующее с другим продуктом пользователя | HTTP 409 Conflict |
| CHK-FOOD-07 | FR11 | Негативный | Удаление продукта, который уже используется в приёмах пищи (`MealEvent`) | HTTP 409 Conflict (защита используемого справочника) |
| CHK-FOOD-08 | FR11 | Позитивный | Удаление продукта, который нигде не используется | HTTP 200/204, продукт успешно удален |

## Модуль 3: Измерения сахара (`glucose-events`)

| ID проверки | Требование | Тип | Описание проверки | Ожидаемый результат |
|---|---|---|---|---|
| CHK-GLU-01 | FR12 | Позитивный | Создание записи замера сахара с валидным значением (например, 5.5 ммоль/л) | HTTP 201/200, замер успешно сохранен |
| CHK-GLU-02 | FR12 | Негативный | Создание замера сахара со значением вне допустимого диапазона (`≤ 0` или `> 50`) | HTTP 422 Unprocessable Entity |
| CHK-GLU-03 | FR16 | Позитивный | Получение списка замеров сахара с пагинацией (`skip`, `limit`) | HTTP 200, возвращается корректный срез замеров |
| CHK-GLU-04 | FR6 | Негативный | Запрос/удаление замера сахара, принадлежащего другому пользователю | HTTP 404 Not Found |

## Модуль 4: Инъекции инсулина (`insulin-events`)

| ID проверки | Требование | Тип | Описание проверки | Ожидаемый результат |
|---|---|---|---|---|
| CHK-INS-01 | FR13 | Позитивный | Создание инъекции инсулина с валидным типом (`short` / `long`) и дозой (например, 6 ед) | HTTP 201/200, инъекция успешно сохранена |
| CHK-INS-02 | FR13 | Негативный | Создание инъекции с недопустимым типом (например, `ultra`) или дозой (`≤ 0` / `> 200`) | HTTP 422 Unprocessable Entity |
| CHK-INS-03 | FR16 | Позитивный | Получение списка инъекций с пагинацией (`skip`, `limit`) | HTTP 200, корректный срез инъекций |

---

## Модуль 5: Приёмы пищи и расчёт ХЕ (`meal-events`)

| ID проверки | Требование | Тип | Описание проверки | Ожидаемый результат |
|---|---|---|---|---|
| CHK-MEAL-01 | FR14 | Позитивный | Создание приёма пищи: указание продукта и массы в граммах | HTTP 201/200, система автоматически рассчитывает `carbs_grams` и `bread_units` по формуле |
| CHK-MEAL-02 | FR15 | Позитивный | Проверка неизменяемости истории: изменение углеводов в справочнике продукта не меняет уже созданные приёмы пищи | Значения `carbs_grams` и `bread_units` в прошлых `MealEvent` остаются прежними |
| CHK-MEAL-03 | FR16 | Позитивный | Получение списка приёмов пищи с пагинацией (`skip`, `limit`) | HTTP 200, корректный срез приёмов пищи |

---

## Модуль 6: Лента, статистика и системные проверки (`events`, `stats`, `healthz`, UI)

| ID проверки | Требование | Тип | Описание проверки | Ожидаемый результат |
|---|---|---|---|---|
| CHK-SYS-01 | FR17 | Позитивный | Запрос ленты событий за сегодня и вчера (`/api/events/recent`) | HTTP 200, события возвращаются объединёнными и отсортированными по времени с учётом часового пояса |
| CHK-SYS-02 | FR18 | Позитивный | Запрос статистики за сегодня и вчера (`/api/stats/recent`) | HTTP 200, возвращаются метрики: среднее/мин/макс сахара, суммы инсулина и углеводов/ХЕ |
| CHK-SYS-03 | FR19 | Позитивный | Запрос эндпоинта проверки живости (`/healthz`) | HTTP 200, статус `ok` |
| CHK-SYS-04 | FR20 | Позитивный | Проверка клиентского рендеринга на XSS (ввод тегов `<script>` в заметки/продукты) | Ввод экранируется в DOM, выполнения вредоносного скрипта не происходит |
