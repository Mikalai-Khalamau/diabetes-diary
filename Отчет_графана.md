# Дз 7 Grafana

Графана установлена в minikube через Helm-chart grafana/grafana в namespace default
В качестве источника данных подключена VictoriaMetrics 

## Дашборд приложения

Построен по методологии 
RED(Rate, Errors, Duration) для http
USE(Utilization, Saturation, Errors) для рантайма
Golden Signals (Latency, Traffic, Errors, Saturation)

1. Панель RPS: sum(rate(http_requests_total[1m])) - показывает нагрузку на сервис
Базовая метрика для понимания, работает ли сервис вообще и сколько трафика обрабатывает

2. Панель HTTP Status Codes: sum by (status) (rate(http_requests_total[5m]))
Распределение ответов по кодам 
Позволяет быстро увидеть, есть ли проблемы: рост 5xx = ошибки сервера, рост 4xx = проблемы на стороне клиента

3. Панель Error Rate: доля ответов 5xx от общего трафика за минуту
100 * (sum(rate(http_requests_total{status=~"5.."}[1m])) / sum(rate(http_requests_total[1m])))
Пороги 1 и 5 процентов - как в SLO доступности описывал

4. Панель Latency p95: 95-й перцентиль времени ответа
histogram_quantile(0.95, sum(rate(http_request_duration_seconds_bucket[1m])) by (le))
Порог 500 мс - как в SLO задержки описывал

5. Панель SLA пробера: процент успешных синтетических проверок за 5 минут
100 * (sum(rate(prober_checks_total{result="success"}[5m])) / sum(rate(prober_checks_total[5m])))
Показывает доступность сервиса как у юзера

6. Панель Memory Usage: потребление памяти Python процессом
process_resident_memory_bytes{app="diabetes-app"}
Пороги 200 мб (желтый) и 256 мб (красный) соответствуют лимиту пода и алерту HighMemoryUsage

7. Панель CPU Usage: утилизация CPU процессом
rate(process_cpu_seconds_total{app="diabetes-app"}[1m]) * 100
Показывает, насколько загружен процессор
Высокая утилизация - значит нужно масштабирование или оптимизация
